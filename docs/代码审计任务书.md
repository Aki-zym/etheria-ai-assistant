# EtheriaAssistant 审计任务

你是资深软件工程师，用第一性原则审计本项目：对每个设计判断回答——它解决什么问题？这是最简解吗？

## 背景

《伊瑟》游戏助手。旧仓库 `EtheriaAssistant`（pywebview + Vue3 前端 + Python 视觉/输入内核）仍在使用；同级新仓库 `EtheriaMaa`（MaaFramework 引擎）P0 骨架已验证。已定决策：主线只开发 PC 客户端，模拟器路线封存待接入，旧仓库冻结为只修致命问题、功能逐个迁出。唯一蓝本 `docs/Etheria升级总计划.md`，另有三份支撑文档（MAA 架构精读 / MaaFramework 迁移设计 / AgentDebug 通道设计）。

## 要做的事

1. **确认目标**：读 README 与四份文档、git log 和 git status，先写清——项目要解决什么问题、当前阶段、成功标准、你理解的决策链。这步理解错了后面全错，必须最先做。
2. **审计划**：总计划各阶段（P1~P4、并行工作包 DX）是否可实现、验收是否齐备；文档之间有无矛盾；列出未验证假设（每条标注：已验证 / 赌注）；检查模拟器封存是否贯彻——计划与代码里有无预埋分支。
3. **审架构**：分层依赖方向是否与蓝本一致；任务注册表是否唯一入口；把总计划第四章八条防屎山红线当检查单，列出违规。
4. **审代码**：先审工作区未提交 diff——每一处是第一性解法，还是在已判退役的代码上堆补丁；再全库扫重复实现、魔法数字、死代码、无人使用的抽象与配置。会被带进未来的代码（EtheriaMaa、注册表、打包、前端接线）从严，旧 `core/` 从宽。
5. **审过度工程**：找出"为想象中的未来而建、当前无人使用"的东西，代码和文档都算，每项判决：保留 / 简化 / 删除。重点复核：截图四路兜底链、多尺度模板匹配、AgentDebug 步进会话、总计划 P4 按需项、拟人化点击。
6. **复核旧账**：《MAA-架构分析与Etheria升级路线》第六节列过的历史问题，逐条标注"仍存在 / 已解决 / 恶化"；重点找文档没写的新问题，不要重复报告旧账。

只报告、不改代码；发现附 file:line 证据，不确定的标注存疑。
