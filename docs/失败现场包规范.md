# 失败现场包规范

> v1 · 2026-09-06 · P0A 交付物
> 旧仓库轻量实现（`core/_base/scene_pack.py`），新引擎时代按本规范映射。

---

## 一、定位

**失败现场包 = 任务失败的终点证据包。** 出问题时，"当时在干什么、看到什么、说过什么、环境什么样"一次打包落盘，人不在场也能事后定案。

与《AgentDebug通道设计》的分工：

| | AgentDebug 会话目录（`debug/runs/`） | 失败现场包（`scene_packs/`） |
|---|---|---|
| 性质 | **过程观测**：持续日志 + 周期帧 | **失败终点**：触发点自动落一次 |
| 谁产出 | 调试运行器 / 看门狗 | 任务运行时的钩子 |
| 关系 | 看门狗产出的"死因 + 末帧 + 日志尾"是七要素的**进程级子集** | 语义的完整定义处 |

## 二、七要素

| 要素 | 落点 | 说明 |
|---|---|---|
| 任务 | `info.json` → `task` | 任务 id 与入参快照 |
| 节点 | `info.json` → `node` | 失败位置；旧仓库无节点概念，取触发点描述或回溯位置（`文件:行 函数`），新引擎时代 = 引擎回调的节点名 |
| 时间 | `info.json` → `time` | 毫秒精度 ISO 时间 |
| 原始帧 | `frame.png` | 优先取**任务最后成功帧**（识别失败场景下它就是出错时画面）；无缓存才失败瞬间补截，来源写入标注帧与 info |
| 标注帧 | `frame_annotated.png` | 最近动作坐标画红十字圈 + 顶部文字条（任务 / 节点 / 错误 / 时间 / 帧来源） |
| 日志尾 | `log_tail.txt` | 最近 300 行，毫秒时间戳（环形缓冲，GUI 与 CLI 同源） |
| 环境 | `info.json` → `environment` | 版本、git 提交号、窗口标题/句柄/矩形、屏幕分辨率、Python、冻结态、配置快照（全部非敏感项） |

## 三、目录与保留

```
scene_packs/
└── 20260906-153042-137-zhuxian/     ← 时间戳(含毫秒)-任务
    ├── info.json
    ├── frame.png
    ├── frame_annotated.png
    └── log_tail.txt
```

- 自动只保留**最近 20 份**，超出即删最旧；已加入 `.gitignore`。
- 打包版落在 exe 同目录，开发版落在仓库根。

## 四、触发点（旧仓库）

1. **注册表出口**（覆盖全部 15 个任务）：`core/tasks.py: run_task` 异常 → 落包 → 原样抛出；
2. **自有 except 分支**：`GameBot.run_dungeon`、UI 智壳入口等已捕获异常处补落；
3. **全局兜底钩子**：`scene_pack.install()`（`ui/app.py` 与 `scripts/run.py` 启动时调用）挂主线程 + 子线程异常钩子，任务名记为 `uncaught-<线程名>`；
4. **去重**：2 秒内同类型同消息的异常只落一份（第 1 层落包后再抛时，兜底钩子不会重复落盘）。

## 五、纪律

- 现场包是诊断设施：**自身任何异常不得影响主流程**（全部静默吞掉，只打标准输出一行）。
- 七要素缺项降级而非失败：无帧则缺图并注明，无 git 则提交号记 `(unknown)`。
- 标注帧用 PIL 绘制（Windows 微软雅黑），规避文字识别库的中文字体乱码问题。

## 六、新引擎映射（EtheriaMaa，P1 起）

总计划"贯穿不变量 4：失败现场按任务落盘"由 MaaFramework 引擎内建失败存图承接，映射到本规范：

- 引擎失败存图（原始 + 标注）→ `frame.png` / `frame_annotated.png`；
- 编排层补 `info.json`（任务、**节点 = 引擎结构化回调的节点名**、环境）与 `log_tail.txt`（结构化回调流）；
- 目录命名与 20 份保留策略沿用；DX-4 接线时看门狗产物映射到同一结构。
